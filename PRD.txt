PRD — GestCom
Application web de gestion commerciale multi-rôles
Version : 1.0
Statut : Document de conception
Type : Application web responsive
Nom du produit : GestCom — Gestion Commerciale
Cible : PME, commerces, magasins et entreprises disposant d'une ou plusieurs équipes commerciales.
1. Vision du produit
GestCom est une application web de gestion commerciale permettant à une entreprise de centraliser dans une seule plateforme :
- les ventes ;
- les produits ;
- les stocks ;
- les clients ;
- les fournisseurs ;
- les utilisateurs ;
- les magasins ;
- les objectifs commerciaux ;
- les rapports et statistiques ;
- le suivi des performances des vendeurs ;
- la gestion des permissions.
L'application repose sur un système multi-rôles avec trois espaces principaux :
1. Administrateur
2. Manager
3. Vendeur
Chaque rôle possède une interface adaptée à ses responsabilités et n'accède qu'aux fonctionnalités qui lui sont autorisées.
Les écrans fournis servent de référence visuelle et fonctionnelle pour la direction artistique de l'application.

3. Objectifs du produit
3.1 Objectif principal
Créer une solution commerciale permettant à une entreprise de gérer son activité quotidienne depuis une seule application.
3.2 Objectifs secondaires
GestCom doit permettre de :
- réduire la gestion manuelle ;
- centraliser les données commerciales ;
- suivre les ventes en temps réel ;
- contrôler les stocks ;
- connaître les performances des vendeurs ;
- suivre les objectifs ;
- gérer plusieurs magasins ;
- contrôler les accès ;
- générer des rapports ;
- faciliter la prise de décision.

6. Création du premier compte administrateur
C'est une étape fondamentale du produit.
Lorsqu'une entreprise lance GestCom pour la première fois et qu'aucun administrateur n'existe, l'application doit afficher une option :
Créer le compte administrateur

Informations demandées
Entreprise
- Nom de l'entreprise
- Logo
- Adresse
- Téléphone
- Email
- éventuellement site web
Administrateur
- Nom
- Prénom
- Email
- Téléphone
- Nom d'utilisateur
- Mot de passe
- Confirmation du mot de passe
Après validation
Le système :
1. crée l'entreprise ;
2. crée le compte administrateur ;
3. associe l'administrateur à l'entreprise ;
4. initialise les paramètres par défaut ;
5. redirige l'administrateur vers son tableau de bord.
7. Système d'invitation des utilisateurs
L'administrateur ne doit pas créer directement les mots de passe des autres utilisateurs.
Il crée une invitation contenant :
- nom ;
- prénom ;
- email ;
- rôle ;
- magasin affecté ;
- éventuellement téléphone.
Exemple :
Nom : Koffi Jean
Email : koffi@entreprise.com
Rôle : Vendeur
Magasin : Magasin 1

GestCom envoie ensuite une invitation à l'utilisateur.
8. Première connexion d'un utilisateur invité
Lorsqu'un vendeur ou manager reçoit son invitation :
Étape 1
Il clique sur :
Accepter mon invitation

Étape 2
Il vérifie ses informations.
Étape 3
Il crée lui-même son mot de passe.
Étape 4
Son compte devient actif.
Étape 5
Il est redirigé automatiquement vers son espace.
Règle de sécurité importante
L'administrateur ne voit jamais le mot de passe définitif du vendeur ou du manager.
L'administrateur peut uniquement :
- renvoyer une invitation ;
- désactiver un compte ;
- réactiver un compte ;
- déclencher une réinitialisation du mot de passe.

Sécurité
Le système doit prévoir :
- mots de passe hashés ;
- sessions sécurisées ;
- expiration de session ;
- protection contre les tentatives répétées ;
- contrôle des permissions côté serveur ;
- validation des données ;
- protection CSRF si architecture concernée ;
- journalisation des actions sensibles.

Authentification
- hash sécurisé des mots de passe ;

- expiration de session ;
- récupération de compte.

   ↓

VENDEUR

39. Performance
L'application doit :
- charger rapidement ;
- éviter les requêtes inutiles ;
- paginer les grandes listes ;
- optimiser les images ;
- utiliser le lazy loading lorsque nécessaire ;
- mettre en cache certaines données ;
- éviter de charger toutes les données d'un dashboard en une seule fois.

47. Principe UX fondamental
L'application ne doit pas seulement être jolie.
Elle doit être :
Simple à comprendre + rapide à utiliser + cohérente + sécurisée + responsive.

Le vendeur doit pouvoir effectuer une vente avec un minimum d'étapes.
Le manager doit pouvoir comprendre la performance de son équipe rapidement.
L'administrateur doit pouvoir comprendre l'état global de l'entreprise depuis son dashboard.

50. Résultat attendu
À terme, GestCom doit donner l'impression d'être une véritable solution SaaS commerciale professionnelle.
Un utilisateur doit pouvoir :

Le tout depuis une seule plateforme, avec une interface différente et pertinente pour chaque rôle.

Conclusion
Ce PRD définit donc GestCom comme une application commerciale multi-tenant/multi-rôles, et non comme un simple dashboard statique. Les quatre maquettes fournies deviennent la référence de l'expérience visuelle, tandis que le PRD ajoute toute la logique nécessaire derrière ces interfaces : création du premier administrateur, invitations, activation des comptes, séparation Admin/Manager/Vendeur, permissions, ventes, stock, clients, magasins, objectifs, rapports et sécurité.
